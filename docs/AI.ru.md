## Что реализовано

Отдельный процесс читает публичные свечи основного таймфрейма и 1h, рассчитывает EMA20/50, ATR, изменения цены за 1/4/16 свечей и отношение текущего объёма к среднему за 20 свечей. Получает до 20 свежих RSS/Atom-заголовков за 24 часа и передаёт данные локальной модели Ollama. По умолчанию используются BBC World и CoinDesk; можно явно задать до пяти других HTTPS-лент. Недоступность/пустая лента отражается в `news_coverage`, а не заменяется выдуманными новостями.

Это исследовательский наблюдатель: возвращает bullish/bearish/neutral, субъективную confidence, объяснение на русском, риски и ID использованных новостей. Он не исполняет сделки, не получает ключи Bybit, не вызывает торговые инструменты и не меняет торговый сигнал. Заголовки считаются недоверенными данными; модель получает запрет выполнять инструкции из них. Строгая проверка JSON снижает ошибки формата, но не доказывает истинность рассуждений модели.

Текущая EMA-стратегия продолжает работать отдельно. Это намеренный первый этап проверки: результат ИИ нельзя считать улучшением стратегии без измерений. Модель не читает весь интернет, не видит полный стакан, funding, экономический календарь или каждое изменение цены. Новости — заголовки, а не проверенные полные статьи. Частота опроса по умолчанию 5 минут плюс время загрузки/генерации; это не низколатентная торговля.

## Установка Ollama на Mac

1. Установите Ollama с https://ollama.com/download/mac и запустите приложение. Требования к macOS проверяйте на странице загрузки; установленный Python не определяет совместимость Ollama.
2. В новом терминале:

```bash
ollama pull qwen2.5:3b
ollama list
```

`qwen2.5:3b` — стартовая небольшая модель, а не доказанно лучший торговый аналитик. Она занимает место на диске и использует RAM/CPU/GPU; скорость зависит от Mac. Для более сильной модели при достаточной памяти можно отдельно загрузить `qwen2.5:7b` и указать её через `--model`. Облачные API и подписка Claude не нужны; расходы на электричество и ресурсы компьютера остаются. Модель обслуживается только через локальный `127.0.0.1:11434`.

## Первый запуск аналитика

Обновите проект из GitHub, сохраните старые журналы/состояние и свои локальные изменения. В новой версии активируйте окружение и установите пакет. Для известных на Mac проблем сборки cryptography:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install --only-binary=cryptography -e .
python -m unittest discover -s tests -v
python -m dual_futures_bot.ai_advisor --exchange bybit --timeframe 15m --cycles 1
```

При успехе будет `status: ok`, а в `reports/ai-advisor.json` — отчёт, снимок рынков, заголовки и модель. При ошибке `status: error` и тип исключения; старый успешный отчёт заменяется ошибкой. Например, ConnectionError может означать недоступность Ollama или рынка, HTTPError — ответ API с ошибкой, ValueError — неподходящий ответ модели/данные. Проверяйте Ollama, наличие модели и сеть; полные запросы/секреты не печатаются.

Непрерывная работа (не отправляет ордера):

```bash
python -m dual_futures_bot.ai_advisor --exchange bybit --timeframe 15m --model qwen2.5:3b
```

`--interval 300` задаёт паузу между анализами, минимум 60 секунд. `--feed https://example.org/feed.xml` заменяет стандартные ленты; параметр можно повторить до пяти раз. Укажите действительный RSS/Atom URL, а не страницу новостей. Redirect автоматически не принимается: укажите конечный HTTPS-адрес. Даты без часового пояса, публикации из будущего или старше суток пропускаются. Дубликаты заголовков удаляются. Если лента изменила адрес или блокирует доступ, это видно в покрытии.

## Подключение вывода к торговому боту

Во второй вкладке терминала активируйте то же окружение. Сначала без Demo-ордеров:

```bash
python -m dual_futures_bot --exchange bybit --mode realtime-paper --timeframe 15m --limit 200 --ai-report reports/ai-advisor.json --state reports/paper-with-ai.json
```

Теперь внутри `analysis.ai_advisor` появится оценка ИИ. Если настроен Telegram, она попадёт в сводку. Для отображения рядом с существующей Demo-стратегией добавьте `--ai-report reports/ai-advisor.json` к её обычной команде и сохраните её прежний `--state`; не запускайте второй торговый процесс на том же аккаунте/символе.

Время исходного снимка, а не время завершения генерации определяет свежесть. Отчёт старше 10 минут, для другого символа/биржи/таймфрейма, с ошибкой или неверной схемой отображается как `unavailable_or_stale`. Торговля по нему не запускается и обычная стратегия не блокируется. Медленный ИИ не задерживает проверку paper-стопов: модель работает в другом процессе.

Ctrl+C у аналитика останавливает только анализ. Последний отчёт станет устаревшим через 10 минут. Ctrl+C у торгового бота не закрывает биржевые позиции.

## Что сохраняется и как проверять пользу

`reports/ai-advisor.json` — последний снимок, `reports/ai-history.jsonl` — история всех оценок и ошибок, включая входные рыночные признаки, заголовки, модель и время. Пути задаются через `--report` и `--history`. Один процесс на один report; файл `.lock` удаляется только после подтверждения, что процесс остановлен. Для разных рынков используйте разные report/history. История растёт без ротации; следите за диском. Файлы игнорируются Git. Ключей в них нет.

`confidence` — самооценка модели, не вероятность прибыльной сделки. Даже валидный ответ может быть неверным, новости могут быть шумом или уже учтены ценой. Обученная модель знает часть истории, поэтому её анализ старых новостей может содержать будущую информацию; не выдавайте такой бэктест за честное испытание.

Следующие улучшения стоит проверять по очереди:

1. Сохранить базовый результат стратегии и параллельные прогнозы ИИ на данных, ещё неизвестных на момент решения. Нужны разные рыночные режимы и достаточное число сделок, а не один успешный круг.
2. Измерять чистый PnL, просадку, комиссии, funding, оборот, число сделок и средний результат сделки. Одинаковые цены и расходы для сравниваемых вариантов.
3. Добавить проверяемые spread/funding/ликвидность и фильтр слишком маленького ожидаемого движения относительно издержек. Затем тренд/флэт и общий риск нескольких позиций.
4. Только после независимого сравнения испытывать ИИ-фильтр входов или отдельную paper-стратегию без EMA-пересечений. Это ещё не реализовано. Нельзя оценивать прибыльность наблюдателя по PnL существующей стратегии: он её решения не меняет.

Маленькая прибыль не проще гарантируется, чем большая: частые сделки с небольшими целями особенно чувствительны к комиссиям и спреду. Прибыли эта интеграция не обещает.

## Проверено

Офлайн-тесты покрывают схему ответа, ссылки на переданные новости, даты RSS/Atom, пустые/недоступные ленты, истечение свежести и запрос Ollama без торговых tools. Настоящая модель и RSS-доступ в облаке не проверены; модель нужно скачать и проверить на Mac. Подтверждения роста доходности нет.

## Если Ollama медленная или отменяет запрос через две минуты

В ранней версии клиент ждал ответа 120 секунд. На CPU обработка входного текста и генерация могут занять больше. Текущая версия выводит этапы загрузки рынка, новостей и ожидания модели; таймаут чтения увеличен до 300 секунд, а бюджет ответа уменьшен до 512 токенов. HTTP 500 в логе Ollama рядом с отменой запроса через 2 минуты может быть следствием клиентского таймаута, но другие причины 500 требуют проверки лога.

Для медленного Mac:

```bash
python -m dual_futures_bot.ai_advisor --exchange bybit --timeframe 15m --cycles 1 --timeout 480 --max-tokens 512
```

`--timeout` принимает 30–540 секунд и относится к ожиданию ответа Ollama; это не общий предел времени всего анализа. `--max-tokens` принимает 256–2048, по умолчанию 512. Слишком маленький бюджет может обрезать JSON: `TruncatedModelResponse` с подсказкой означает, что нужно попробовать 768 токенов. Само увеличение таймаута модель не ускоряет. По-прежнему действует предел свежести снимка 10 минут, даже если модель отвечает успешно.

Если скорость слишком мала, можно отдельно скачать `ollama pull qwen2.5:1.5b` и запустить с `--model qwen2.5:1.5b`; меньшая модель может хуже рассуждать и соблюдать формат. Не запускайте несколько запросов/агентов одновременно. Во время анализа модель расходует ресурсы Mac, но торговый процесс не ожидает её ответ.
