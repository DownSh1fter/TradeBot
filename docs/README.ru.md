Новые режимы опроса и демо-ордеров описаны в [руководстве по анализатору и Bybit Demo](REALTIME.ru.md). Ниже — руководство по историческому режиму.

Это исторический симулятор фьючерсной стратегии, а не постоянно работающий торговый сервис. Он получает публичные свечи OHLCV Binance или Bybit через CCXT, рассчитывает сигналы и моделирует сделки. Аккаунт, API-ключи, база данных и фоновые службы не нужны. Требуются Python 3.11+ и HTTPS-доступ к бирже. Биржи запускаются отдельно; арбитража между ними нет.

## Установка

```bash
git clone https://github.com/DownSh1fter/TradeBot.git
cd TradeBot
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

В Windows PowerShell вместо создания и активации окружения используйте `py -3.11 -m venv .venv` и `.venv\Scripts\Activate.ps1`. Дальнейшие команды выполняйте из корня репозитория с активным окружением.

## Запуск

```bash
python -m dual_futures_bot --exchange binance --symbol BTC/USDT:USDT --timeframe 15m --limit 1000 --equity 10000
python -m dual_futures_bot --exchange bybit --symbol BTC/USDT:USDT --timeframe 15m --limit 1000 --equity 10000
python -m dual_futures_bot --help
```

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--exchange` | обязательный | `binance` или `bybit` |
| `--symbol` | `BTC/USDT:USDT` | Унифицированный символ swap-контракта CCXT |
| `--timeframe` | `15m` | Поддерживаемый биржей интервал свечей |
| `--limit` | `1000` | Запрошенное число свечей, 60–1500 |
| `--equity` | `10000` | Положительный конечный начальный капитал |

Биржа может вернуть меньше свечей или установить меньший лимит. Незакрытая свеча удаляется; должно остаться минимум 60 закрытых свечей. При необходимости увеличьте лимит. Постраничной загрузки истории нет.

## Как работает симуляция

1. Пересечение EMA(20) выше EMA(50) даёт long, ниже — short. EMA начинается с простого среднего. ATR(14) использует сглаживание Уайлдера.
2. Сигнал известен после закрытия свечи. Вход происходит на открытии следующей с неблагоприятным проскальзыванием. Одновременно открыта максимум одна позиция.
3. Начальный стоп расположен в 2 × ATR от входа. Объём — минимум из `капитал × 0.0025 / расстояние_до_стопа` и `капитал × 0.25 / цена_входа`. Целевой риск не включает комиссии и проскальзывание; гэп может увеличить убыток.
4. Если цена открытия перескочила действующий стоп, выход происходит по открытию. Иначе противоположный сигнал закрывает позицию на открытии. Затем проверяется стоп внутри свечи, в том числе для новой позиции. На закрытии обновляется trailing stop для следующей свечи: стоп long только повышается, short — понижается.
5. Комиссия составляет 0.05% номинала с каждой стороны, неблагоприятное проскальзывание — 0.02% на входе и выходе.
6. Реализованный дневной убыток от 1% капитала на начало суток UTC запрещает новые входы до следующих суток. Это не гарантия ограничения убытка и не стоп по плавающему результату. Оставшаяся позиция закрывается по закрытию последней свечи.

Настройки риска находятся в `RiskConfig` файла `src/dual_futures_bot/simulator.py`, периоды EMA — в `strategy.py`. Это настройки Python API, а не параметры CLI. Пример:

```python
from dual_futures_bot.market_data import fetch_candles
from dual_futures_bot.simulator import RiskConfig, simulate
candles = fetch_candles('bybit', 'BTC/USDT:USDT', '15m', 1000)
report = simulate(candles, RiskConfig(initial_equity=5000, risk_fraction=0.001))
print(report['net_pnl'])
```

## Отчёты и ограничения

JSON сохраняется относительно текущей папки: `reports/<биржа>_<символ>_<таймфрейм>.json`. Повторный запуск той же комбинации перезаписывает отчёт; скопируйте его отдельно для сохранения истории. В консоли выводится сводка без списка сделок.

Отчёт содержит начальный/итоговый капитал, чистый PnL и доходность, число сделок, долю прибыльных сделок, комиссии, число заблокированных суток UTC и сделки со стороной, ценами, объёмом, временем (Unix в миллисекундах), чистым PnL и причиной выхода. `max_drawdown_fraction` — просадка реализованного капитала на выходах из сделок, без плавающей внутрисделочной просадки. Доли умножайте на 100 для процентов. Отдельного gross PnL нет: чистый PnL плюс комиссии даёт результат до комиссий, но с проскальзыванием.

Не моделируются funding, ликвидации, маржинальный учёт, ликвидность стакана, шаг объёма и минимальные ордера биржи. Формула PnL линейная; для корректных единиц используйте линейные USDT-контракты. OHLC не восстанавливает полный путь цены внутри свечи. Короткий тест с такими допущениями не подтверждает будущую прибыльность. Исторический режим не отправляет ордера и не ведёт общий портфель двух бирж; исполнение Bybit Demo описано отдельно.

## Проверки и решение проблем

```bash
python -m unittest discover -s tests -v
```

Тесты работают без сети: проверяют стратегию/риск, порядок исполнения стопов, числовую валидацию и загрузку через подставную биржу. Они не подтверждают доступ к API. GitHub Actions запускает набор на Python 3.11 и 3.12.

При `ModuleNotFoundError` активируйте окружение и повторите установку. Для неверного контракта/таймфрейма проверьте список swap-рынков биржи. При HTTP 403/451, ошибках DNS или прокси проверьте сетевые разрешения и региональную доступность; не отключайте TLS-проверку. CCXT сначала загружает метаданные рынков, поэтому могут понадобиться дополнительные API-хосты. Обычно это `api.bybit.com`, `api.binance.com`, `fapi.binance.com`, `dapi.binance.com`. Для публичных данных ключи не нужны.

Проверка в облаке: офлайн-тесты прошли, но сетевой прокси среды отклонил обращения к биржам с CONNECT 403. Запуск на реальных данных остаётся непроверенным до разрешения доступа.

## Структура проекта

`market_data.py` — закрытые свечи; `indicators.py` — EMA/ATR; `strategy.py` — сигналы; `simulator.py` — объём/исполнение/отчёт; `__main__.py` — CLI; `tests/` — офлайн-регрессии.
