## 1. Обновление без потери состояния

Остановите прежнего трейдера и отдельного агента через Ctrl+C; Ollama можно оставить. Остановка не закрывает позиции. Сверьте позиции/ордера в Bybit Demo и сохраните резервную копию reports. Не удаляйте pending_order или state ради обновления.

```bash
cd ~/Downloads/TradeBot-git
git status --short
git pull --ff-only
source .venv/bin/activate
python -m pip install --only-binary=cryptography -e .
python -m unittest discover -s tests -v
```

Если Git сообщает о локальных изменениях, сохраните их до продолжения. Старый `ema-cross` остаётся по умолчанию для совместимости; новый режим включается явно.

## 2. Проверка новой стратегии без ключей

```bash
python -m dual_futures_bot --exchange bybit --mode realtime-paper --strategy trend-pullback --timeframe 15m --limit 200 --equity 1000 --fee-rate 0.00055 --cycles 1 --state reports/paper-trend.json
```

Сначала появляется `role: session`, затем `role: trader`. Это торговый цикл, а не один ИИ. В `decision` есть `action` и `reason`; `wait` не означает зависание. При пригодных данных записывается состояние и журнал. Одна итерация не гарантирует сигнал/сделку.

`--fee-rate 0.00055` означает модельные 0.055% с каждой стороны. Это пример предположения для сравнения, не чтение вашего тарифного уровня из Bybit. Укажите свой актуальный тариф. `--slippage-rate` по умолчанию 0.0002 (0.02% с каждой стороны). Менять расходы у уже сохранённого state без сверки нельзя: они входят в его идентичность.

## 3. Один запуск с ИИ — без ручного управления двумя Python-процессами

Убедитесь, что Ollama работает и модель скачана. Старый отдельно запущенный `ai_advisor` остановите, чтобы не конфликтовать по report lock.

```bash
python -m dual_futures_bot --exchange bybit --mode realtime-paper --strategy trend-pullback --timeframe 15m --limit 200 --equity 1000 --fee-rate 0.00055 --with-ai --state reports/paper-trend.json
```

Трейдер сам запускает наблюдателя. Данные ИИ по умолчанию:

- последний отчёт: `reports/ai-advisor.json`;
- история: `reports/ai-advisor.history.jsonl`;
- stdout/stderr агента: `reports/ai-advisor.log`.

Их можно переместить через `--ai-report`; история/лог будут рядом с указанным файлом. Для наблюдения за агентом из другой вкладки:

```bash
tail -n 20 reports/ai-advisor.log
```

Дополнительные параметры: `--ai-model qwen2.5:3b`, `--ai-timeout 480`, `--ai-interval 60`, `--ai-max-tokens 512`. Первого ответа ждать не нужно для обычных сигналов: ИИ не управляет ордерами. Его ошибка/neutral не запрещает технически разрешённую сделку. Пока ответ не готов, отчёт может быть unavailable_or_stale.

В дочерний процесс не передаются переменные BYBIT_* и TELEGRAM_*. При остановке трейдера он останавливает только своего дочернего агента, не приложение Ollama. Если уже используете отдельного агента, вместо `--with-ai` укажите только `--ai-report reports/ai-advisor.json`.

## 4. Demo в одной команде

Сначала убедитесь, что старый трейдер остановлен, а по выбранному символу нет позиции/заявок. Новая стратегия не подхватывает чужую позицию: `Unmanaged position` означает необходимость сверки в Bybit, а не повод удалять файлы. Переход со старой политики выполняйте на плоском счёте; не закрывайте/не отменяйте ничего вслепую.

В текущей вкладке задайте BYBIT_DEMO_API_KEY/SECRET и необязательные Telegram-переменные [по инструкции](START_HERE.ru.md). Значения не вставляются в код/чат. Затем:

```bash
python -m dual_futures_bot --exchange bybit --mode bybit-demo --strategy trend-pullback --timeframe 15m --limit 200 --equity 1000 --fee-rate 0.00055 --with-ai --state reports/demo-trend.json
```

Это может отправлять Demo-ордера. Для одной попытки добавьте `--cycles 1`; не ожидайте, что за неё успеет ответить ИИ. Для запуска без модели уберите `--with-ai`.

Старый `reports/demo-bybit.json` сохраните: это другая политика. Новый `demo-trend.json` разрешён только после сверки старых позиций/заявок. При перезапуске новой стратегии используйте её прежний state, параметры и тарифы. Отдельный общий lock в `reports/.execution_bybit_<symbol>.lock` запрещает два Demo-трейдера для символа из одного checkout даже с разными state. Это локальная защита, не распределённая блокировка разных компьютеров/папок. Один аккаунт/символ не должен обслуживаться другими ботами или ручными сделками.

## 5. Точные правила trend-pullback-v1

Правила фиксированы и не оптимизировались по пользовательскому PnL:

- минимум 60 закрытых непрерывных свечей, EMA20/50 и ATR14;
- направление задаёт EMA20 относительно EMA50; разрыв минимум 0.25 ATR;
- наклон EMA20 за три свечи должен совпадать с направлением;
- ATR/цена от 0.05% до 5%; относительный объём последней свечи не меньше 0.5 среднего предыдущих 20;
- цена не дальше одного ATR от EMA20; за последние три свечи должен быть контакт с зоной EMA20 ± 0.25 ATR;
- последняя свеча должна подтвердить отскок по направлению тренда;
- расстояние до цели 3 ATR должно быть не меньше двух оценок полного кругового расхода (комиссия, проскальзывание, в онлайне также спред);
- в онлайне спред не выше 0.08%, пригодный timestamp стакана и смещение текущей цены от сигнального закрытия не больше ATR.

Расстояние до цели — геометрический фильтр расходов, не прогноз движения и не положительное математическое ожидание. Ликвидность за пределами лучших bid/ask и funding этим фильтром не проверяются. Историческая симуляция и онлайн используют один causal policy, но прогрев EMA и длина доступной истории могут давать различия около порогов.

Выходы: фиксированный Stop Loss 2 ATR, Take Profit 3 ATR, слом EMA-тренда или максимум 24 свечи удержания. Trailing в этой политике нет. Для Demo стоп/цель передаются бирже при входе, их наличие проверяется после исполнения. Результат заявки опрашивается read-only до 10 раз; повторной отправки при таймауте нет. Неоднозначный статус/неподтверждённая защита оставляют pending_order и останавливают процесс для сверки.

После закрытия — три свечи cooldown. Биржевой стоп/цель, закрывшие позицию между опросами, обнаруживаются по исчезновению позиции; причина и реализованный PnL этим наблюдением не доказываются. Их смотрите в Bybit.

## 6. Риск и исполнение

- База размера — меньшее из заданного equity и наблюдаемого USDT equity.
- Риск по расстоянию до округлённого стопа с запасом на модельные комиссии/проскальзывание — до 0.25%; номинал до 25% базы.
- Новая политика не отправляет номинал выше свободного USDT: она не рассчитывает на плечо для увеличения позиции. Плечо/маржу API не переключает.
- Минимумы/шаг/max amount проверяются. Если расчётный размер не помещается в минимальный ордер, `below_exchange_minimum` и ожидание, без увеличения риска.
- Убыток от дневного стартового USDT equity на 1% меньшего из стартового equity и заданного --equity блокирует входы, но не защитные выходы (при базе 1000 бюджет 10 USDT, даже если Demo-баланс больше). При наличии Bybit coin equity используется оно, иначе wallet плюс плавающий PnL выбранной позиции; используйте отдельный USDT-счёт. Это не гарантированный потолок убытка.
- Если quote устарел во время чтения аккаунта, вход блокируется `quote_expired_before_order`.
- Цены, комиссии, проскальзывание и funding фактических сделок определяет биржа; модельные ограничения не гарантируют точный результат.

## 7. Почему нет входа: смотрите decision.reason

| Причина | Значение |
|---|---|
| `awaiting_ema_cross` | Выбрана старая стратегия, нового пересечения нет |
| `awaiting_next_closed_candle` | Текущая закрытая свеча уже обработана |
| `weak_trend` / `trend_slope_conflict` | Тренд не прошёл критерии |
| `price_too_far_from_ema` / `no_recent_pullback` | Нет подходящего отката |
| `rebound_not_confirmed` | Отскок не подтверждён |
| `low_volume` / `low_volatility` / `high_volatility` | Фильтры рынка |
| `target_too_small_for_costs` / `spread_too_wide` | Недостаточное расстояние до цели или слишком широкий спред |
| `entry_price_moved` | Текущая цена ушла от сигнальной |
| `below_exchange_minimum` | Размер по риску ниже минимума биржи |
| `insufficient_free_balance_without_leverage` | Недостаточно свободного USDT для номинала |
| `post_exit_cooldown` | Пауза после закрытия |
| `daily_loss_limit` | Входы заблокированы дневным лимитом |
| `position_open` | Уже есть позиция |

В `events` будут `demo_order` и, при внешнем закрытии, `position_closed_observed`. `status: closed` относится к ордеру, не обязательно к позиции. Telegram показывает последнее решение в сводке. Пустые события не означают сбой, а наличие сделки не означает прибыль.

## 8. Что отправлять для диагностики

`reports/demo-trend.jsonl` — добавляемый журнал принятых торговых циклов и отклонённых котировок; там price, analysis, decision, equity, positions, events. `reports/demo-trend.json` — текущее состояние. `reports/ai-advisor.history.jsonl` — отдельная история мыслей модели. Не путайте эти роли. Журналы растут без ротации; контролируйте диск. API-ключи не записываются, но это финансовая информация — перед публикацией проверьте файл.

Последние решения:

```bash
tail -n 3 reports/demo-trend.jsonl
```

Если трейдер упал до записи, нужен также traceback из его терминала. При pending_order не перезапускайте/не создавайте новый state до сверки client ID, позиции и ордеров в Bybit. При зависшем общем execution lock проверяйте отсутствие всех трейдеров перед ручным удалением lock; state/журналы не удаляйте.

## 9. Сравнение на замороженной истории

На вашем компьютере с доступом к публичному API можно сохранить один одинаковый набор для обеих политик. Ордеров эта команда не отправляет:

```bash
python - <<'PY'
import json
from pathlib import Path
from dual_futures_bot.market_data import fetch_candles
rows = fetch_candles('bybit', 'BTC/USDT:USDT', '15m', 1000)
path = Path('reports/BTCUSDT-15m-sample.json')
path.parent.mkdir(parents=True, exist_ok=True)
if path.exists():
    raise SystemExit('Dataset already exists; preserve it or choose a new name')
path.write_text(json.dumps([list(vars(c).values()) for c in rows]))
print('Saved closed candles:', len(rows))
PY
python -m dual_futures_bot.benchmark --input reports/BTCUSDT-15m-sample.json --output reports/benchmark.json --equity 1000 --fee-rate 0.00055 --slippage-rate 0.0002
```

Нужно минимум 240 свечей. Сравниваются фиксированные политики с одинаковыми расходами: первые 2/3 и последующая последняя треть. До 200 предшествующих свечей используются для прогрева теста без сделок в прогреве. Параметры не подбираются, победитель автоматически не включается. В отчёте есть SHA256 входа, количество сделок, чистый результат, комиссии и просадка. `max_mark_to_market_drawdown_fraction` измеряет модельное equity по закрытиям свечей, не максимальную внутрисвечную просадку.

Это ещё не доказательство прибыльности: нет funding/ликвидаций, реального стакана и ограничений объёма биржи; стоп/цель в одной OHLC-свече трактуются консервативно (сначала стоп). 1000 свечей — короткий период, недостаточный для решения о реальных деньгах. Нужны дальнейшие независимые периоды, разные режимы и forward Demo.

## 10. Что проверено и что остаётся

Офлайн-сценарии проверяют вход по уже существующему тренду без нового пересечения, long/short, отсутствие принудительных входов во флэте/при дорогой сделке, неизменность прошлых решений при добавлении будущих свечей, paper-вход/выход с журналом, attached SL/TP, cooldown, дневной лимит, минимумы, ожидание статуса без повторной заявки и жизненный цикл дочернего агента.

На синтетическом случайном движении новая политика получала убытки после расходов. Это намеренно отражено в [отчёте проверки](VALIDATION.md): больше сделок не означает лучше. Актуальную историю Bybit/Binance в облаке получить не удалось (прокси CONNECT 403). Текущие рыночные результаты и исполнение новой политики на вашем Demo ещё не подтверждены. Нельзя называть эту версию прибыльной по результатам unit-тестов или старого успешного smoke-теста.

Стратегия остаётся исследовательской, только paper/Demo. Реального режима нет. Следующий критерий готовности — ваши торговые журналы и независимые сравнения после всех расходов, а не число сообщений агента.
