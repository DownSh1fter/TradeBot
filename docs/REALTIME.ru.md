# Анализ рынка и Bybit Demo

[English](REALTIME.en.md) · [Основное руководство](README.ru.md)

## Что добавлено

Три режима: `backtest` (по умолчанию), `realtime-paper` и `bybit-demo`. Анализатор опрашивает REST API каждые 10 секунд. Это обновление с задержкой опроса, а не поток WebSocket и не анализ новостей/ИИ. Он использует закрытые свечи графика: EMA20/EMA50 определяют тренд и пересечение, ATR14 — волатильность. Вход блокируется при ATR/цене выше 5%. Анализ, сигналы и события печатаются как JSON.

Сигнал появляется только при новом пересечении на последней закрытой свече. Если рынок уже находится в тренде, бот ждёт следующего пересечения. Окно EMA пересчитывается по загруженным свечам. Незакрытые, устаревшие, пропущенные или некорректные свечи не принимаются. Котировка должна иметь timestamp не старше 60 секунд.

## Проверка без ключей

После установки из основного руководства:

```bash
python -m dual_futures_bot --exchange bybit --mode realtime-paper --timeframe 15m --limit 200 --poll-seconds 10 --state reports/paper-bybit.json
```

`--cycles 1` выполняет одну итерацию вместо бесконечного цикла. В paper-режиме вход/выход рассчитывается по последней полученной цене с модельными комиссиями и проскальзыванием. Стоп проверяется на каждом опросе, trailing обновляется на новой закрытой свече. Между опросами движение может быть пропущено. Это отличается от свечного бэктеста.

## Подключение Bybit Demo

1. В Bybit включите **Demo Trading**, создайте API-ключ именно в демо-среде с разрешением торговли. Demo Trading и Testnet — разные среды. Используйте отдельный демо-аккаунт без ручных сделок и других ботов.
2. Для линейных USDT perpetual выберите режим позиции **one-way**. Настройте маржу/плечо в демо-интерфейсе заранее: бот не меняет их. Пополните виртуальный USDT-баланс.
3. Передайте `BYBIT_DEMO_API_KEY` и `BYBIT_DEMO_API_SECRET` через защищённое окружение процесса. Не записывайте их в репозиторий, отчёты или чат. `.env` автоматически не читается. Подписывание HMAC требует настоящего секрета внутри процесса: прокси-подстановка секрета в HTTPS-запрос не заменяет такую передачу.
4. Запустите сначала одну итерацию:

```bash
python -m dual_futures_bot --exchange bybit --mode bybit-demo --symbol BTC/USDT:USDT --timeframe 15m --limit 200 --equity 1000 --cycles 1 --state reports/demo-bybit.json
```

Уберите `--cycles 1` для непрерывного опроса. Ордер будет отправлен только при наличии нового сигнала; отсутствие сделки само по себе не ошибка. Все приватные API-вызовы направлены на `api-demo.bybit.com`, адрес проверяется перед отправкой. Боевой режим отсутствует.

## Исполнение и риск Demo

Для входа используется рыночный ордер, объём округляется к шагу биржи. База расчёта — минимум доступного общего USDT equity аккаунта и `--equity`. Риск 0.25%, максимальный номинал 25% этой базы, стоп 2×ATR. Слишком маленький ордер отклоняется локально; бот не повышает риск ради минимального объёма. Стоп прикрепляется к ордеру через Bybit; после подтверждённого исполнения проверяется наличие стопа у позиции. Фактические цены и комиссии определяет биржа.

При противоположном сигнале текущая позиция закрывается `reduceOnly`; немедленного входа в обратную сторону в том же сигнале нет. В Demo trailing stop пока не обновляется — действует начальный биржевой стоп. Дневная просадка equity аккаунта от 1% относительно первого опроса суток UTC запрещает новые входы до следующих суток; не закрывает автоматически позицию. Не используйте этот аккаунт для других операций: баланс и позиции сверяются с биржей без разделения по ботам.

## Состояние, остановка и ошибки

Файл `--state` содержит рынок, режим, настройки риска, обработанную свечу и журнал. Запись атомарная; один файл нельзя использовать для разных рынков/режимов. Для каждого процесса нужен отдельный файл, но запускать два Demo-процесса на одном аккаунте/символе нельзя. Файл `.lock` защищает один путь от двойного запуска. После аварийного завершения удаляйте оставшийся `.lock` только убедившись, что процесс больше не работает.

Ctrl+C останавливает опрос, **не закрывает Demo-позиции и не отменяет ордера**. Проверьте их в Bybit. Paper-позиция сохраняется и возобновляется при следующем запуске. Во время остановки paper-стоп не работает; биржевой Demo-стоп остаётся на бирже, если был принят.

Сетевые ошибки останавливают процесс. До отправки ордера сохраняется `pending_order` с `client_id`. При таймауте, неизвестном статусе или неподтверждённом стопе автоматического повтора нет. Найдите заявку по этому ID в Bybit, проверьте исполнения, позицию, стоп и открытые ордера. Только после сверки и остановки процесса сделайте резервную копию JSON и установите `pending_order` в `null`; не удаляйте весь state, иначе можно повторить сигнал. При неподтверждённом стопе сначала защитите или закройте позицию через демо-интерфейс.

Пропущенные сигналы во время простоя не воспроизводятся: анализируется только последняя закрытая свеча. В журнале Demo хранятся ID/статусы ордеров, а не полный бухгалтерский отчёт; исполнения и PnL смотрите в Bybit. Журнал растёт в JSON, для длительной эксплуатации нужна отдельная система хранения.

## Сеть и статус проверки

Разрешите HTTPS к `api-demo.bybit.com` и `api.bybit.com`; загрузка метаданных CCXT может требовать дополнительные хосты. Не отключайте TLS-проверку. В облаке обнаружены сетевые ограничения, ключи Demo отсутствуют. Пройдены офлайн-тесты логики и API-адаптера с подставными ответами, но реальная загрузка/отправка Demo-ордера ещё не подтверждены. Начните с небольшого виртуального капитала и проверьте результат в интерфейсе Bybit.

## Исправление времени котировки Bybit

CCXT может возвращать тикер Bybit без timestamp, хотя цена присутствует. В таком случае бот получает стакан и использует середину лучшего bid/ask с timestamp стакана. В анализе `quote_source` равен `orderbook_midpoint`, иначе `ticker_last`. Это ориентир для расчёта, а не гарантированная цена исполнения. Котировки старше 60 секунд, из будущего, без времени биржи или с некорректным стаканом отклоняются. Время получения запроса не подставляется вместо времени биржи. Если ошибка свежести сохраняется, проверьте автоматическую синхронизацию даты и времени macOS и сетевую задержку.
