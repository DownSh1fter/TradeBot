# Полный запуск на Mac: TradeBot, Bybit Demo, Ollama и Telegram

[English version](START_HERE.en.md) · [Главная](../README.md)

Это пошаговая инструкция для текущей версии проекта. Основная рабочая папка во всех примерах — `~/Downloads/TradeBot-git`. Команды рассчитаны на Terminal / терминал VS Code в macOS, bash или zsh. Знак `$`, стрелки приглашения и текст `(.venv)` вводить не нужно: копируйте только содержимое блоков.

## 1. Что делает каждый компонент

| Компонент | Назначение | Отправляет ордера? |
|---|---|---|
| `backtest` | Историческая симуляция | Нет |
| `realtime-paper` | Виртуальные сделки на текущих данных | Нет |
| `bybit-demo` | EMA-стратегия с ордерами на Bybit Demo | Да, только Demo |
| `ai_advisor` | Анализ графиков и новостей через локальную модель | Нет |
| Telegram | Исходящие уведомления | Нет; команды торговли не поддерживаются |
| `demo_smoke` | Однократный вход и выход без сигнала | Да, только Demo |

ИИ пока **наблюдатель**: его отчёт виден в анализе и уведомлениях, но не меняет входы/выходы. EMA20/50 и прежние ограничения риска продолжают определять сделки. Работоспособность программы не доказывает доходность стратегии.

## 2. Установить необходимые приложения

- [VS Code](https://code.visualstudio.com/).
- [Python для macOS](https://www.python.org/downloads/macos/): проект требует 3.11+, примеры используют 3.12.
- Git. Проверка: `git --version`. Если macOS предлагает установить Command Line Tools, завершите установку.
- [Ollama для Mac](https://ollama.com/download/mac), только если нужен ИИ. Проверьте актуальную совместимость вашей macOS на сайте Ollama.
- Bybit Demo Trading, только для демо-ордеров. Demo Trading — не Testnet и не основной счёт.

Проверки в терминале:

```bash
python3.12 --version
git --version
```

Если команда не найдена, сначала установите соответствующее приложение и откройте новый терминал. Python 3.9 из macOS для проекта не подходит.

## 3. Скачать проект один раз

Если папка `TradeBot-git` уже существует, не клонируйте поверх неё: переходите к разделу обновления.

```bash
cd ~/Downloads
git clone https://github.com/DownSh1fter/TradeBot.git TradeBot-git
cd ~/Downloads/TradeBot-git
ls pyproject.toml
```

Последняя команда должна показать `pyproject.toml`. Если нет, вы не в корне проекта.

В VS Code выберите **File → Open Folder → Downloads → TradeBot-git**, затем **Terminal → New Terminal**. Если дерево файлов исчезло: Cmd+Shift+P → `View: Reset View Locations`, затем Cmd+Shift+E.

### Если ранее скачивали ZIP (`TradeBot-main`)

`git pull` предназначен для Git-копии, а не ZIP. Остановите старые процессы, проверьте позиции в Bybit и сохраните старую папку. Если новая `TradeBot-git` только что создана и ещё не содержит `reports`, можно перенести состояние:

```bash
cp -R ~/Downloads/TradeBot-main/reports ~/Downloads/TradeBot-git/
```

Если старой папки `reports` нет, этот шаг не нужен. Если `reports` есть в обеих папках, не объединяйте их вслепую: сначала сравните и сохраните резервные копии. Сохраните отдельно свои изменения кода. Старое `.venv` копировать не нужно; создайте новое окружение в новой папке. Не запускайте одновременно старую и новую копии стратегии.

## 4. Создать окружение и установить зависимости

Из корня проекта:

```bash
cd ~/Downloads/TradeBot-git
python3.12 -m venv .venv
source .venv/bin/activate
python --version
python -m pip install --upgrade pip
python -m pip install --only-binary=cryptography -e .
python -m unittest discover -s tests -v
```

После активации перед приглашением обычно появляется `(.venv)`. В конце тестов должно быть `OK` и ненулевое число выполненных тестов. Офлайн-тесты не проверяют ваши API-ключи или доступ к бирже.

`--only-binary=cryptography` запрещает сборку этой зависимости из исходников, чтобы избежать известной проблемы Rust/maturin на Mac. Если совместимого готового пакета нет, пришлите версии macOS/Python и текст ошибки; не отключайте проверку TLS и не изменяйте требования проекта наугад.

### В каждой новой вкладке

Всегда начинайте с:

```bash
cd ~/Downloads/TradeBot-git
source .venv/bin/activate
```

Окружение Python и переменные API — разные вещи. Активация `.venv` не загружает ключи. Введённые через `export` значения относятся к текущему процессу shell и его дочерним процессам; на автоматический перенос в другую вкладку рассчитывать нельзя. `.env` бот автоматически не читает.

## 5. Проверить публичные данные без ключей и ордеров

```bash
python -m dual_futures_bot --exchange bybit --mode realtime-paper --timeframe 15m --limit 200 --cycles 1 --state reports/paper-check.json
```

Ожидается JSON с `analysis`, `events` и без traceback. `events: []` нормально: сигнала может не быть. Отчёт состояния сохранится в `reports/paper-check.json`.

Отдельно исторический бэктест:

```bash
python -m dual_futures_bot --exchange bybit --mode backtest --timeframe 15m --limit 200 --equity 1000
```

## 6. Создать и ввести ключи Bybit Demo

В веб-интерфейсе переключитесь в **Demo Trading → API**. Создайте системный API-ключ с чтением и торговлей контрактами (Read-Write / Orders). Разрешение вывода не требуется. Включите one-way для выбранного линейного USDT perpetual; плечо/маржу настройте в Demo заранее — бот их не переключает. На счёте должен быть виртуальный USDT.

Если настроена привязка IP, в списке должен быть внешний IP текущего подключения/VPN. Локальный IP `192.168...` не подходит. При смене VPN/сети внешний IP может измениться. Используйте действующий Demo-ключ; ключ, опубликованный в чате или скриншоте, следует отозвать и заменить.

### Куда вставлять значения — строго по шагам

Вкладку, где будете запускать торгового бота, дальше называем **C**. В ней сначала активируйте окружение из раздела 4.

**Шаг 1.** Скопируйте и выполните только эту строку. Имя переменной НЕ заменяйте своим ключом:

```bash
read -r -s BYBIT_DEMO_API_KEY
```

После Enter терминал молча ждёт ввод. Теперь вставьте **только API Key** через Cmd+V и нажмите Enter. Символы и звёздочки не показываются — это нормально.

**Шаг 2.** Когда вернулось приглашение терминала, выполните:

```bash
export BYBIT_DEMO_API_KEY
echo
```

**Шаг 3.** Выполните отдельно:

```bash
read -r -s BYBIT_DEMO_API_SECRET
```

Вставьте **только API Secret**, затем Enter. После возврата приглашения:

```bash
export BYBIT_DEMO_API_SECRET
echo
```

Не вставляйте сразу весь сценарий вместе с секретами: `read` ожидает отдельный ввод. Никаких кавычек вокруг значения при скрытом вводе не нужно. Не вводите токен вместо имени переменной в команде.

### Проверить формат, не показывая секреты

```bash
python - <<'PY'
import os
for name in ('BYBIT_DEMO_API_KEY', 'BYBIT_DEMO_API_SECRET'):
    value = os.environ.get(name, '')
    valid = bool(value) and value.isascii() and not any(c.isspace() for c in value)
    print(name, 'format OK' if valid else 'empty or contains invalid characters')
PY
```

Это проверяет только наличие и символы, а не права ключа. Не используйте `env`, `printenv`, `echo "$...SECRET"` или скриншоты значений для диагностики. Секрет нужен внутри процесса для HMAC; прокси-подстановка вместо настоящего секрета не подходит.

## 7. Telegram — необязательный шаг во вкладке C

1. В Telegram через проверенного **@BotFather** выполните `/newbot`. Сохраните токен.
2. Откройте **своего** созданного бота и нажмите Start / отправьте `/start`.
3. Для личных уведомлений узнайте свой числовой `Id` через **@userinfobot**. Ему не нужен токен вашего бота. Chat ID — не телефон и не @username. Для группы нужен ID группы и право бота отправлять сообщения; данные счёта увидят участники этого чата.

Выполните отдельно:

```bash
read -r -s TELEGRAM_BOT_TOKEN
```

Вставьте токен через Cmd+V → Enter. Затем:

```bash
export TELEGRAM_BOT_TOKEN
echo
```

Теперь отдельно запросите chat ID (он будет видимым):

```bash
read -r TELEGRAM_CHAT_ID
```

Введите только числовой ID → Enter, затем:

```bash
export TELEGRAM_CHAT_ID
export TELEGRAM_STATUS_SECONDS='300'
```

Проверка доставки, без торговли:

```bash
python - <<'PY'
import os
from dual_futures_bot.telegram import Telegram
if not os.environ.get('TELEGRAM_BOT_TOKEN') or not os.environ.get('TELEGRAM_CHAT_ID'):
    print('Token or chat ID is empty')
else:
    bot = Telegram.from_env()
    try:
        print('Sent' if bot.send('Connection test', {'message': 'TradeBot connected; no orders sent'}) else 'Delivery failed')
    finally:
        bot.close()
PY
```

Должно прийти сообщение. Telegram отправляет запуск, остановку/ошибку, сделки/изменения позиции и сводку раз в 300 секунд. Минимум интервала — 30 секунд. При сбоях сообщения могут потеряться, повторной очереди нет. Бот не принимает торговые команды через Telegram.

Чтобы полностью отключить Telegram перед запуском:

```bash
unset TELEGRAM_BOT_TOKEN TELEGRAM_CHAT_ID
```

## 8. Ollama — вкладка A или приложение

Установите Ollama в Applications и запустите приложение. Если оно уже обслуживает модель, второй сервер запускать не надо.

Проверки:

```bash
ollama --version
ollama list
```

Если `ollama` не найдена, используйте полный путь:

```bash
/Applications/Ollama.app/Contents/Resources/ollama --version
```

Если сервер недоступен, выделите **вкладку A** и запустите:

```bash
/Applications/Ollama.app/Contents/Resources/ollama serve
```

Оставьте её открытой. Если порт уже занят, проверьте запущенное приложение/сервер вместо запуска ещё одного.

В другой вкладке скачайте модель один раз:

```bash
/Applications/Ollama.app/Contents/Resources/ollama pull qwen2.5:3b
```

Модель работает локально, без облачного API-ключа. Требует память, диск и вычисления Mac. Первая загрузка/генерация может занять минуты. В логе сервера `n_gen` и tokens/s показывают генерацию; HTTP 500 не означает успешный ответ — проверяйте итог агента.

## 9. Проверить и оставить работающим ИИ — вкладка B

Откройте **вкладку B**, активируйте окружение:

```bash
cd ~/Downloads/TradeBot-git
source .venv/bin/activate
python -m dual_futures_bot.ai_advisor --exchange bybit --timeframe 15m --cycles 1 --timeout 480 --max-tokens 512
```

Сначала появятся этапы загрузки рынка/новостей/ожидания Ollama. Итог должен содержать `status: ok`. Если `status: error`, прочитайте `error_type` и `hint`; сам факт появления JSON не означает успешного анализа.

Для непрерывной работы уберите `--cycles 1`:

```bash
python -m dual_futures_bot.ai_advisor --exchange bybit --timeframe 15m --timeout 480 --max-tokens 512
```

Пауза между завершёнными анализами — 300 секунд плюс время следующего анализа. `--timeout 480` — таймаут чтения ответа Ollama, не гарантированное время всего цикла. Если `TruncatedModelResponse`, попробуйте `--max-tokens 768`. Если Mac не справляется, можно скачать `qwen2.5:1.5b` и указать `--model qwen2.5:1.5b`; качество может снизиться.

Агент использует основной график и 1h, EMA/ATR, изменения цены и относительный объём. Заголовки RSS учитываются за 24 часа, это не полный интернет или проверенные статьи. `news_coverage` показывает ошибки: например, CoinDesk в пользовательской проверке возвращал `ValueError`, поэтому нельзя считать криптоновости подключёнными только по `status: ok` всего отчёта. Модель может ответить по-английски, несмотря на инструкцию русского языка.

Файлы:

- `reports/ai-advisor.json` — последний отчёт;
- `reports/ai-history.jsonl` — история оценок/ошибок;
- `reports/ai-advisor.json.lock` — блокировка одного процесса.

`confidence` — субъективная оценка модели, не вероятность прибыли. `bias: neutral` не является сигналом закрыть позицию.

## 10. Запустить торговлю — вкладка C

Во вкладке C должны быть активны `.venv`, ключи Demo и, по желанию, Telegram из разделов 6–7. **Сначала остановите другие торговые процессы**, включая старую папку `TradeBot-main`. Один процесс стратегии на аккаунт/инструмент; отдельные файлы состояния не делают параллельный запуск безопасным.

Одна итерация с подключённым отчётом ИИ:

```bash
python -m dual_futures_bot --exchange bybit --mode bybit-demo --timeframe 15m --limit 200 --equity 1000 --cycles 1 --ai-report reports/ai-advisor.json --state reports/demo-bybit.json
```

Это уже торговая команда: при сигнале может отправить Demo-ордер. Успешное чтение аккаунта не проверяет право отправки ордеров, пока вход не произошёл.

Непрерывно:

```bash
python -m dual_futures_bot --exchange bybit --mode bybit-demo --timeframe 15m --limit 200 --equity 1000 --ai-report reports/ai-advisor.json --state reports/demo-bybit.json
```

Без ИИ просто уберите `--ai-report reports/ai-advisor.json`; Ollama/аналитик тогда не нужны. Без ордеров замените режим на `realtime-paper` и используйте отдельный `--state reports/paper-with-ai.json`.

`--equity 1000` — база/потолок расчёта объёма, а не размер каждого ордера или гарантированный лимит потерь. Текущие настройки риска: 0.25% на расстояние до стопа, номинал до 25% расчётной базы, блок новых входов при дневном снижении equity от 1%. Учитываются реальные биржевые минимумы/шаг объёма. Комиссии, проскальзывание и гэпы могут увеличить убыток. Для Demo начальный стоп 2×ATR; автоматическое подтягивание Demo-стопа пока не реализовано.

Бот проверяет рынок примерно раз в 10 секунд плюс время API/уведомлений. Сигнал EMA нужен на новой закрытой свече 15m; часы ожидания без входа нормальны. ИИ при этом анализирует независимо и торговые сигналы не заменяет.

## 11. Как читать результат и проверить сделку

| Поле | Значение |
|---|---|
| `signal: null` | Нового сигнала стратегии нет |
| `events: []` | Эта итерация новых ордеров не отправила |
| `type: demo_order` | Подтверждён результат отправленного Demo-ордера |
| `status: closed` у ордера | Ордер завершён/исполнен; это не означает закрытие позиции |
| `filled`, `average` | Исполненный объём и средняя цена, если вернула биржа |
| `reduce_only: false` | Ордер на вход |
| `reduce_only: true` | Сокращение/закрытие позиции |
| `paper_equity: null` | Нормально для режима Demo |
| `quote_source: orderbook_midpoint` | Цена-ориентир из середины bid/ask с временем стакана |
| `ai_advisor.status: ok` | Свежий валидный отчёт ИИ прочитан |
| `unavailable_or_stale` | Отчёт отсутствует, с ошибкой, для другого рынка или старше 10 минут |

В Bybit Demo проверьте **Positions**, наличие Stop Loss, **Order History / Trade History**. Успешный вывод программы не заменяет сверку стопа/позиции на бирже. Демо-журнал не является полным бухгалтерским учётом. При стопе, исполненном биржей, новый `demo_order` в торговом цикле может не появиться; Telegram обнаруживает изменение снимка позиции на следующем опросе. Полное открытие/закрытие между опросами может быть пропущено уведомлениями.

Свежесть ИИ считается от исходного снимка, не конца генерации. Если модель долго думает, отчёт может быстро истечь. Временные метки в JSON — Unix milliseconds; Telegram указывает UTC. Для просмотра используйте свои локальные часы с учётом часового пояса.

## 12. Разовый тест открытия и закрытия без графика

Остановите все стратегии/тесты; проверьте отсутствие позиции и ордеров по BTCUSDT. Во вкладке C:

```bash
python -m dual_futures_bot.demo_smoke --execute --max-notional 250
```

Отправляется минимальный допустимый market buy со страховочным стопом, затем market sell `reduceOnly` на фактический объём. Потолок опорного номинала — меньшее из 250 USDT и 25% свободного Demo USDT. Это не атомарная операция: между ордерами есть API-задержка. При ошибке позиция может остаться. Ожидаемый успех:

```text
DEMO ROUNDTRIP OK: no position and no open orders for this symbol.
```

`reports/demo-smoke.json` создаётся эксклюзивно. При `FileExistsError` сначала прочитайте журнал и сверьте Bybit:

```bash
cat reports/demo-smoke.json
```

Не удаляйте журнал для обхода ошибки. Новый `--journal reports/demo-smoke-2.json` допустим только после сверки предыдущего теста и отсутствия позиции/заявок. См. [подробности теста](DEMO_SMOKE.ru.md).

## 13. Остановка, сон Mac и следующий запуск

- Ctrl+C в C останавливает торговый цикл, **не закрывает позиции и не отменяет биржевые ордера**.
- Ctrl+C в B останавливает аналитика, не торговлю. Отчёт вскоре станет устаревшим.
- Закрытие A / Ollama останавливает модель; агент получит ошибку при следующем запросе.
- Не допускайте сна/отключения сети Mac, если рассчитываете на непрерывный цикл. После остановки/сна проверяйте биржу. Принятый биржевой стоп может продолжать действовать, но это нужно подтвердить в интерфейсе.
- При следующем запуске используйте прежний файл состояния и те же настройки. Не создавайте новый state ради обхода `pending_order`, несовпадения настроек или другой ошибки.

Для каждого нового терминала заново активируйте окружение и задайте необходимые переменные. Ключи сохранять в исходники или публиковать не нужно; этот проект автоматически не хранит их на диске.

## 14. Обновление из GitHub

Сначала Ctrl+C во вкладках B/C. Проверьте позиции/стопы и сохраните резервные копии state, журналов и своих изменений. Ollama можно оставить работающей.

```bash
cd ~/Downloads/TradeBot-git
git status --short
git pull --ff-only
source .venv/bin/activate
python -m pip install --only-binary=cryptography -e .
python -m unittest discover -s tests -v
```

Если `git pull` сообщает о конфликте/локальных изменениях, остановитесь и сохраните их; не используйте `reset --hard`, `git clean` или удаление `reports` как способ обновления. Отчёты игнорируются Git и не обновляются из репозитория. После тестов снова запустите B/C, сохранив исходные пути состояния. Если вкладка C прежняя и переменные не очищены, вводить ключи повторно не требуется.

### Оставшийся `.lock`

Сначала проверьте процессы:

```bash
pgrep -fl 'dual_futures_bot.ai_advisor'
pgrep -fl 'dual_futures_bot --exchange'
```

Остановите нужный процесс через его терминал. Только когда уверены, что соответствующий процесс не работает, для стандартного отчёта агента:

```bash
rm reports/ai-advisor.json.lock
```

Для стандартного торгового state, **после сверки Bybit и журнала**:

```bash
rm reports/demo-bybit.json.lock
```

Эти команды удаляют только блокировку, не state. Если вы использовали другие пути `--report`/`--state`, имя lock тоже другое. Для `demo_smoke` существующий `.json` — журнал, а не lock, его так удалять нельзя.

### Безопасно узнать ответ Telegram

Если общий тест пишет Delivery failed, выполните следующую проверку; она не печатает токен:

```bash
python - <<'PY'
import os
import requests
token = os.environ.get('TELEGRAM_BOT_TOKEN', '').strip()
chat = os.environ.get('TELEGRAM_CHAT_ID', '').strip()
if not token or not chat:
    print('Token or chat ID is empty')
else:
    try:
        r = requests.post(f'https://api.telegram.org/bot{token}/sendMessage',
                          json={'chat_id': chat, 'text': 'TradeBot connection test'}, timeout=10)
        data = r.json()
        print('HTTP:', r.status_code)
        print('Result:', data.get('description', 'Sent' if data.get('ok') else 'Unknown response'))
    except Exception as exc:
        print('Connection error:', type(exc).__name__)
PY
```

При обращении за помощью присылайте тип/текст ошибки, `pwd`, версии Python/macOS и последние строки лога без ключей/токенов. Не публикуйте весь процесс environment.

### `quote_unavailable` и устаревший отчёт ИИ

В текущей версии отклонение котировки не завершает обычный торговый цикл: бот пропускает попытку без ордеров. В логе `reason`, `source`, `age_seconds`, затем при восстановлении `quote_recovered`. Допускается опережение времени биржи до 2 секунд; возраст свыше 60 секунд не допускается. Если предупреждения продолжаются, проверяйте Bybit/сеть/часы; не считайте отсутствие ордеров подтверждением закрытой позиции. Paper-стоп не исполняется без пригодной цены.

`ai_advisor: unavailable_or_stale` не вызывает ошибку цены. Проверьте вкладку B, последний `status`/`hint`, правильность пути и совпадение таймфрейма. Для медленной модели суммарные время генерации и пауза между анализами могут дать промежутки без свежего отчёта. Можно остановить только агента и запустить его с `--interval 60 --timeout 480 --max-tokens 512` вместо стандартной паузы 300 секунд; это увеличит нагрузку, но не гарантирует свежесть. Предел свежести остаётся 10 минут, старые рекомендации не становятся торговыми сигналами.
